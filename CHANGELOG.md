# Changelog

## Unreleased

## 0.3.0 - 2026-11-10

- Player profile in the admin page: per build, when the server first and last heard from the player, the device the client reported (model, OS, app and SDK version, the optional `client` object of `/verify`, `/restore`, `/entitlements`, `/paywall`), the custom attributes the game set (new `POST /attributes`) and the billing country of the newest purchase. New table `player_profile`; `last_seen` is rewritten at most once an hour. The release workflow checks `PurserInfo.Version` too.

- Integrations choose how revenue is sent, like Adapty: **Gross revenue**, **Proceeds after store commission** or **Proceeds after store commission and taxes** (`revenue`: `gross`, `proceeds`, `net` in the settings of GA4, AppsFlyer, Adjust, Tenjin and AppMetrica). The commission comes from the Store fee settings (per app, lowered after a subscription's first paid year) and is fixed when the event is queued; the tax is estimated from the buyer's billing country with the standard VAT / GST rate (`purser_core::tax`). The webhook and the Cloud Storage export carry all three amounts (`price_micros`, `proceeds_micros`, `net_micros`) with `country` and `commission_percent`.

- **Copy Unity config** on an app's Products tab copies its builds and products (with default prices) for the Unity inspector without running the new app wizard; Unity previews the changes and merges them (add and update, or match the admin panel).

- Unity config import and export carry prices: a pasted Unity config's fallback prices become the default prices of products that have none on the server (the server's price wins), and the wizard's Unity config includes the default prices. The Unity package fills `StoreProduct` from them where the store shows no price, and its inspector opens the admin page.

- Apps can have a display name (the pencil next to an app's name in the admin page): shown in the header, the sidebar, the apps list, the command menu, revenue and player pages. The app key (`game_key`) stays as it is. New table `app_profile`, reducer `admin_set_app_name`; `seed.py` loads and exports `app_names.json`; the MCP `list_apps` tool returns the name.

## 0.2.0 - 2026-11-10

- Unity package: the config is keyed by store (`builds`, per-product `storeIds`), so one game can have several web builds (Stripe and Xsolla); **Copy config for admin panel** in the inspector; fixes for purchases without a product id, Amazon receipts the server rejected, web purchases without attribution and paywall, hanging purchases and game handler exceptions. Breaking for the package API: see `unity/com.yevhenii.purser/CHANGELOG.md`.
- Admin page: the Unity config goes both ways. **Paste from Unity** on the first step of the new app wizard fills in the builds (merged by store and app id) and the products from the JSON the Unity config inspector copies; **Import from Unity** on an app's Products tab compares the pasted products with the app's (new, changed, same), saves them to every build with the store's own product id and keeps existing prices, and lists builds the app does not have instead of creating them. The config is keyed by store (`builds: [{store, appId}]`, `products: [{id, type, storeIds}]`); the wizard's Unity config now lists every build (Steam and web included) and per-store product ids. Configs in the old format (`androidAppId`, ...) are refused with a hint to copy them again from Unity.

## 0.1.0 - 2026-11-10

First public release.

- Catalog import from the App Store: "Import from App Store" on the Products tab and in the new app wizard lists the app's in-app purchases (with the real consumable / non-consumable kind) and subscriptions (with their period) through the App Store Connect API, next to the existing Google Play import. Needs an App Store Connect API Team key (new optional account secrets `apple_connect_key_id`, `apple_connect_private_key_p8`; the issuer id is shared). An app with several importable builds gets a button for each. Importing a product the store lists without a price keeps its configured price.
- App Store refund requests: when a player asks Apple for a refund (`CONSUMPTION_REQUEST`), the server answers within the 12 hours Apple gives with whether the purchase was delivered and used, and optionally the outcome it recommends (decline for delivered purchases, a full refund when the delivery failed, prorated for subscriptions). Per build: `game_app.apple_refund_mode` (`off`, `inform`, `prefer`), set on the app's Delivery tab. Only for players who consented in the game (`attribution.refund_data_consent`, `SetRefundDataConsent` in the Unity package). Answers are queued in `apple_consumption_outbox`, retried until the deadline and listed in the purchase history; the setup check shows the mode.
- Integration health: for every build and integration the module keeps the last sent event, the last failure (retried or dropped, with the error) and the last event skipped because the client did not send the device id the integration needs (`integration_health`). The Integrations tab shows it under each build, and the setup check reports failures and missing device ids instead of only checking the settings.
- Fixed: the setup check reported the keys of GA4, Tenjin, Adjust, AppMetrica, the webhook integration and Cloud Storage as missing even when they were set; it now reads the key of every integration kind.
- `seed.py`: new optional files `paywalls.json`, `placements.json`, `alerts.json` (channels and rules) and `settings.json` (public address, store fee); `--export DIR` writes a database's configuration in the seed format (keys of the secrets only, never their values); `--init` is a guided first setup that writes the seed files, generates the notification secrets, uploads them, offers the Google Play catalog import, runs the setup check and prints the store console URLs and the Unity `BillingConfig` JSON. `seed.py` now calls the admin reducers over HTTP like the other scripts, so `PURSER_TOKEN` works for it too.
- MCP server (`server/mcp_server.py`, Python standard library only): Claude Code, Claude Desktop or any MCP client can read apps, the overview, revenue, players, purchases, setup checks, integration health, paywall results and logs through the admin procedures; `--allow-writes` adds manual grants, revokes and requeues. No free-form SQL, no secrets. See docs/mcp.md. `stdb.py` has raising variants of its HTTP helpers (`StdbError`) and takes the token from `PURSER_TOKEN` when set.
- Admin panel demo: a read-only build of the admin page with made-up apps, a year of purchases, subscriptions, integrations and a paywall test, no server and no sign-in (`npm run build:demo`; published with the docs at `/demo/`). Its data comes from `tools/demo_snapshot.py`. README screenshots (light and dark) are taken from it.
- Admin page: the sidebar shows the billing module version (from `/healthz`) next to the title.
- Revenue tree on the Revenue page and an app's Revenue tab: paywall views, trials, purchases, new subscriptions, renewals and expirations, one-time and subscription revenue, gross, refunds and net revenue as linked cards with the change against the previous period and the ratios between them (conversion per view, trial → paid, average purchase, renewal rate, churn, shares of gross, refund rate). `admin_revenue_stats` with `{"summary": true}` also returns `by_product` (with the product kind), `subscriptions` from the daily snapshots and `paywall_views`.
- **Schema cleanup (needs a clean publish of existing databases, `spacetime publish --delete-data`):** the GA4 settings on `game_app` (`ga4_firebase_app_id`, `ga4_api_secret`, `ga4_send_sandbox`) and the old `analytics_schedule` queue are gone (GA4 is a regular integration); Google RTDN and App Store notification health moved from `app_health` to `store_notify_health`, like every other store (`app_health` keeps the `/verify` times); `purchase.analytics_sent` is now `purchase.was_granted` (also in `admin_import_purchases`); the one-off migrations for these are removed. `/verify` no longer lists the ignored `is_sub` field, and the setup check report has only `urls.notify` (no `rtdn` / `apple`).
- Admin page: the Apps list has a Cards / Table switch (remembered in the browser); the table sorts by name, setup check, revenue, products and integrations, with bundle ids and platforms as optional columns.
- Admin page: the app's Keys tab no longer offers the shared `default` scope for builds that have a developer account, so a key set from one app cannot silently replace the key of other apps; the default is set on the Server page.
- Admin page: the app's Integrations tab shows three cards per row; each build has a status (enabled, disabled, key missing, not connected), the card header sums them up, and builds an integration does not apply to (Steam / web for device-id integrations) are one line instead of a row each.
- Admin page: purchases, the player's purchases, revenue by product / country / Apple Ads campaign, monthly subscriptions, paywall variants and recent alerts are sortable tables with pages, resizable columns and a Columns menu (more purchase columns: created, price, country, transaction). Built on the ReUI data grid (MIT).
- Admin page reads less: the Overview takes its counters from one procedure (`admin_overview`, one pass over the ledger instead of a `COUNT(*)` per status) and its revenue from the summary report; the Purchases list (`admin_list_purchases`) applies the app and status filters on the server before the limit, so an app's purchase list is no longer incomplete when other apps had more recent purchases. Pages share one `game_app` load, tabs read their rows by indexed key, paywall results load on request, the revenue report is reused for 30 seconds, and setup checks of several builds run in parallel. "Check now" no longer asks Apple for a test notification: that is a separate button.
- Faster purchases: a Google consumable `/verify` takes 4 database transactions instead of 16 (3 writes instead of 6); `/restore` reads the build, products and store credentials once; notifications and the small client routes read in one transaction. Setup health and attribution are no longer rewritten when nothing changed. The App Store Server API is asked in a known purchase's own environment first.
- Fixed: a fresh `/verify` could answer `pending` when the worker picked the new row up first (rows are now written already taken by the request); a repeated `/verify` did not save the `app_instance_id` of a purchase recorded without one.
- Revenue rebuild in batches: `admin_rebuild_revenue` only starts it, a scheduled step counts 2,500 purchases per transaction once a second (about two minutes for 200k purchases, other calls wait at most one step; live purchases keep being counted once), and `admin_revenue_stats` returns `"rebuilding": true` until it is done. After `admin_import_purchases` the rebuild waits until imports have stopped for 5 minutes instead of running after every batch.
- `admin_revenue_stats` with `{"summary": true}`: totals, the daily series and per-app numbers from the daily aggregates only, without reading the ledger (for overview pages). The full report reads only the purchases its range needs (cohorts, Apple Ads campaigns, trials).
- Lighter worker: an idle run is two short transactions; the large revenue steps run last; a failed FX history download is retried hourly; the "notifications silent" rule is checked hourly; Steam refund reports of builds without sales are polled less often (up to hourly).
- The same delivery error repeated for a purchase is one history row with a repeat count (`purchase_log`); denied / failed Steam orders are deleted after 30 days.
- Fixed: "store notifications silent" alerts for Amazon, Stripe and Xsolla builds looked at Google RTDN; Steam builds (no notifications) are no longer alerted.
- Steam microtransactions: `POST /checkout/steam` (GetUserInfo + InitTxn with the server's publisher key) and `/verify/steam` (FinalizeTxn + QueryTxn); Steam-billed subscription agreements re-checked with GetUserAgreementInfo; refunds and chargebacks from GetReport polling; sandbox interface per build; per-currency item prices (`admin_set_steam_build`, `admin_upsert_steam_items`, `seed.py` `steam.json`); setup check. New secret `steam_publisher_key`.
- Stripe (web): `POST /checkout/stripe` (Checkout Session for a catalog Price), `POST /verify/stripe` (confirm a session after the redirect), signed webhooks at `/notify/stripe?app=` (payments, renewals, subscription ends, refunds, disputes; idempotent); secrets `stripe_secret_key` / `stripe_webhook_secret`; setup check for the key mode and the catalog Prices.
- Xsolla (web): `POST /checkout/xsolla` (Pay Station token for a catalog item), `POST /checkout/xsolla/status`, signed webhooks at `/notify/xsolla?app=` (user validation, payments once per transaction, refunds, subscription cancellations); secrets `xsolla_project_id`, `xsolla_api_key`, `xsolla_webhook_secret`; setup check for the API key and catalog SKUs.
- Stores registry (`purser_core::registry`): a build is one store (`game_app.store`, empty = the platform's default); routes `/verify/<store>` and `/notify/<store>`; the setup check, the admin page (any number of builds per app) and the integrations read the registry.
- Amazon Appstore: Receipt Verification Service (`/verify/amazon`, `amazon_shared_secret`), Real-Time Notifications over SNS with signature verification and the confirmation token in the setup check, subscription re-checks by the worker.
- Paywalls, remote config and A/B tests: placements serve an ordered product list and JSON remote config (`POST /paywall`); tests assign players deterministically by weight; views via `POST /paywall/event`; `/verify` accepts `placement` / `variant_id` / `test_id` / `paywall_id`; results with conversion, USD revenue, ARPU per view and probability to be best; app tab **Paywalls**. See docs/paywalls.md.
- App Store promotional offers: `POST /offers/apple/sign` signs offers (classic signature and the V2 JWS) with the build's In-App Purchase key, bound to the player's `appAccountToken`. See docs/apple-offers.md.
- Revenue: billing country of every purchase and a By country breakdown; estimated proceeds after the store fee (`store_commission_*` settings, Revenue → Store fee); free trials, trial → paid conversion, renewal rate, monthly churn; payer cohorts; revenue by Apple Ads campaign; CSV export of the new tables. Free-trial periods are recorded with price 0 and no longer counted as revenue. Existing databases rebuild the aggregates once.
- Alerts: Telegram, Slack, Discord or signed-webhook messages when deliveries keep failing, store keys are rejected, an integration event is dropped, store notifications go silent or are rejected, or exchange rates stop updating; throttled per rule and app, with "resolved" messages. Settings → Alerts.
- Player profile (`#player/<user_id>`): builds, spending, entitlements, purchase timeline, attribution and delivery problems of one player; found by user id or transaction id (Purchases, Ctrl+K). `admin_revoke_purchase` revokes a purchase from support (the game gets `revoke` with reason `admin`; not a refund).
- Docker Compose setup (`deploy/docker`): SpacetimeDB, module publishing, optional Caddy with automatic HTTPS. Documentation site (MkDocs Material, GitHub Pages) and `docs/openapi.yaml`.
- Integrations: Adjust (S2S events), AppMetrica (Post API revenue), Google Cloud Storage export (one JSON file per event, ready for BigQuery). Apple Ads attribution is collected by the Unity SDK and travels with the events.
- Admin page with many apps: a filter and "N more…" in the sidebar, search and sorting on All apps, a Ctrl+K palette to jump to any app, tab or page. Long values in selects are cut with an ellipsis instead of overlapping the next field.
- Developer account per build, picked from a list (with "New account…") on the Delivery tab and in the wizard, which can put the iOS build on another account; warnings when store keys sit in `default` while several accounts exist.
- The admin page is organized by app: an app page with Setup, Products, Delivery, Integrations, Keys, Purchases and Revenue tabs; shared keys under Settings → Developer accounts, hosts and raw secrets under Settings → Server.
- Integrations: Tenjin (S2S Purchase API) and a signed JSON webhook next to GA4 and AppsFlyer; GA4 is configured as an integration. The admin page shows an integrations catalog.
- New admin page built with React and shadcn/ui (`server/admin-ui`): sidebar navigation, light and dark themes, charts, the same features as before. It is still one self-contained `index.html` served by the module.
- SpacetimeDB 2.14.1.
- Admin panel: **Add a game** wizard, **Check setup** with fix hints (`admin_check_app`), Google Play product import (`admin_list_store_products`), copying products between apps, the public address setting, webhook ping.
- Revenue dashboard: daily aggregates kept with the ledger, active subscriptions and MRR, ECB exchange rates with manual overrides (`admin_revenue_stats`, `admin_rebuild_revenue`, `admin_refresh_fx`, `admin_set_fx_override`). Existing databases get their history on the first worker run.
- Google subscriptions report their price (`recurringPrice`), so renewals carry revenue.
- `seed.py --check` / `--check-only` / `--offline` / `--json`.
- `/healthz` returns the module version.
- Databases created in the dashboard before publishing: the admin page registers the owner and starts the worker (`admin_ensure_worker`).
- Unity: **Paste config from admin panel**, the default server URL is a placeholder that `Validate()` reports.
- Open source: MIT license, CI, release workflow with a prebuilt `purser.wasm`, docs.
